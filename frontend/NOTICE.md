# Frontend source and dependency baseline

The runtime baseline is `@assistant-ui/react` **0.15.23** and
`@assistant-ui/react-markdown` **0.14.18**, from official upstream commit
[`3542d602272a62eddeb8989befc910841c267022`](https://github.com/assistant-ui/assistant-ui/tree/3542d602272a62eddeb8989befc910841c267022).
The upstream packages at this commit have these exact versions. Published peer
dependencies accept React 18 or 19; Markdown accepts `@assistant-ui/react ^0.15.0`.
`package-lock.json` locks the public standalone dependency tree. No workspace,
private UI package, demo model API, cloud history service, or extra database is
configured. The runtime package's transitive `assistant-cloud` package exists in
the published dependency graph but this application does not instantiate a cloud
client or provide cloud credentials.

Official source-copy registrations were checked in
`apps/registry/src/registry.ts` at the fixed commit. Elements are copied source,
not runtime exports. Sources is the **static** elements implementation, not the
runtime Sources badge. ComparisonCard and inline-citation parsing are not used.

Build choices: React/React DOM 19.3.0 and Base UI 1.8.0 follow the fixed starter
published versions. Vite 8.3.2 replaces the starter's Next.js model-route setup to
produce static assets served by existing FastAPI. TypeScript 6.0.2 is a build-only
choice; the removed `baseUrl` avoids its deprecation without changing runtime.
Vitest was locally patched from 4.1.0 to 4.1.11 after npm audit identified
GHSA-82fw-gwwq-j7x9 in the test mocker; runtime versions were unchanged.

Saving uses project-owned `ProposalSummary`, real server Proposal
identity, view invalidation state, explicit object-bound confirmation and
original-action receipts. ApprovalCard and ErrorState are not used as runtime
elements. Display components never fabricate saving or management outcomes.
The same ordinary chat shell includes a project-owned quote directory,
deletion confirmation and data management panels. Vendor provenance copies,
the message primitives and responsive sidebar foundation remain preserved.

Production dependency notices are generated by `build/production-licenses.ts`.
It reads the actual rendered JavaScript module IDs and the original imported
CSS sources (including Tailwind CSS and tw-animate-css), then preserves the exact
installed packages' LICENSE/COPYING and NOTICE/COPYRIGHT files in
`app/ui/assets/third-party-licenses.txt`. The adjacent
`third-party-license-manifest.json` records exact package versions,
package-relative module/CSS paths, and notice SHA-256 hashes. Build/test-only
dependencies are excluded unless their code or styles enter these inputs.
Output order is stable and no local absolute paths or build timestamps are added.
A package lacking license text stops the build unless it has an explicit,
version-and-metadata-hash-bound entry in `vendor/license-exceptions.json`.

The single reviewed exception is `use-composed-ref@1.4.0`. Its published npm
package and official source at npm's recorded gitHead
[`ea2c9d969f2f90a349f4c99338b806423824cea2`](https://github.com/Andarist/use-composed-ref/tree/ea2c9d969f2f90a349f4c99338b806423824cea2)
contain no separate license file. Its package metadata declares MIT, and its
short README and metadata supply no copyright notice or author field. The
unmodified official package.json and a clearly labelled local notice preserving
that declaration plus standard MIT terms are retained in `vendor/licenses/`.
This is not represented as an upstream-provided license text, and no copyright
holder or year has been invented. Any metadata change requires renewed review.
The original assistant-ui vendor copies and separate license remain unchanged.
