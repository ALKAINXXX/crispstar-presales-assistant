# 澄星协作的用途与套餐阅读方法

## 产品身份与资料用途
澄星协作是面向团队任务与项目协作的合成 SaaS，产品内部编号为 chengxing_collab。本文适用于了解产品用途、准备提出协作需求的使用者。澄星售前助手用于核对需求、解释套餐差异和适用条件，是介绍产品的助手，并非另一款产品。本资料集供单用户本地演示使用，其中的能力是既定演示产品事实，不表示当前助手已经实现协作系统。阅读资料时应区分产品说明、客户需求和助手实际执行的功能，不能把产品能力名称当作本项目已经提供的外部服务。

## 从协作目的形成明确需求
适用对象是希望围绕任务和项目开展基础协作的团队。可以先说明要解决的工作问题，再区分必须具备的能力与希望了解的细节；任务与项目协作、基础成员角色和数据导出在三档套餐中均有记录。仅有“让工作更方便”或“功能越多越好”这样的表达，还不足以形成明确的硬需求。任务工作流、甘特图和自动化未在本版目录中建模，不能因为基础协作受支持就承诺这些细节。公司人数也不决定套餐档位，应依据实际功能需求理解各档差异。

## 三档套餐的能力层次
基础版 Basic、团队版 Team、企业版 Business 是同一产品的三档有序套餐，适用于比较基础协作、系统集成和企业管理需求。Basic 包含任务与项目协作、基础成员角色和数据导出；Team 在这些能力上增加产品 API 与 Webhook 通知；Business 继续包含这些能力，并增加 SAML SSO 与审计日志。这个层次说明目录中的包含关系，不等同于对任何客户都能直接使用的保证。SSO 有独立适用条件，私有化部署在三档中都不支持，最高档名称不能覆盖这些限制。

## 支持记录与客户适用性
适用对象是需要比较套餐是否满足自己要求的读者。产品目录的“支持”回答某档是否具备指定能力；客户适用性还需要保留明确要求、未说明的细节和相关条件。不能仅凭套餐名称、公司规模或最高档就得出完全满足的结论。没有明确硬需求时可以了解目录，不能宣称选型已经完成；资料没有回答某项要求，也不能自动改写成不支持。用户主动选择较高且满足需求的档位可以记录其选择原因，但不会改变目录事实或删去原有的硬需求。
