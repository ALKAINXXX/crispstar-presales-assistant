# 基础协作能力的含义与限制

## 任务与项目协作
任务与项目协作适用于希望围绕任务和项目开展基础团队协作的客户，Basic、Team、Business 三档均支持。能力名称表达协作用途，不逐项说明界面、流程或自动处理方式。客户若提出工作流、甘特图、自动化等具体子功能，应将原始要求单独保留，因为本版目录并未建模这些内容。不能将相近的使用场景直接合并为已支持的功能，也不能把使用者对某种工作方式的偏好转成产品承诺。说明基础协作时应同时保留这些细节限制，避免只引用支持结论。

## 基础成员角色
基础成员角色适用于需要区分成员基础角色的团队，Basic、Team、Business 三档均支持。本版资料只说明存在基础角色区分，没有定义角色名称、角色数量和具体权限清单。自定义角色、细粒度权限和身份同步不能直接归入这项能力；如果这些内容是客户的硬需求，应作为尚未建模的要求继续保留。角色说明也不证明某个成员可以执行指定管理操作。讨论权限细节时需要具体资料依据，不能从“基础成员角色”这一名称推导任意授权规则或额外身份功能。

## 协作数据导出
数据导出适用于需要将协作数据导出的客户，Basic、Team、Business 三档均支持。本版说明的是能力存在，未规定导出格式、容量、频率和覆盖范围。用户提出指定文件格式、完整历史导出或定时导出时，应区分这些细节与一般的数据导出需求，不能自动认定都已满足。也不能因细节未说明就把三档的数据导出能力改写为不支持。导出用于取得数据的含义与产品 API 集成、Webhook 通知不同，支持一种能力不能作为另两种能力的证明。

## 能力名称的解释边界
本节适用于已经有具体功能清单、希望对应产品能力的客户。八项受控能力有各自稳定身份，正文解释帮助理解其含义，但不会新增支持矩阵中的能力。基础角色与身份同步、数据导出与双向同步、SAML SSO 与 SCIM 自动开通都不能因名称接近而相互替代。对于目录外要求，资料应保留“未说明”的事实和客户原意，而不是自行选择最相似的能力后宣告支持。未知要求得到新资料前仍需明确处理，增加解释文字不等于已经扩大产品能力或完成需求判断。
